# FreeASVAB app audit and improvement plan (2026-11-03)

Private working notes. Excluded from git via .git/info/exclude.

## Goal

Someone who has never seen the ASVAB opens the app on a phone or tablet, understands in seconds what to do first, gets an honest score estimate, learns from every question, and comes back because they can see themselves improving. The app must feel trustworthy and official in tone without pretending to be a government product.

## Acceptance criteria

- No known data-loss path: an in-progress test can never be silently discarded; question history survives content edits.
- Works on iOS 14+ Safari and Chrome 80+ WebViews (no runtime-only ES2022 APIs).
- Every screen passes ui-audit with zero P0/P1 at 360x740, 601x1007@1.33125 (user's SM-X133 tablet, portrait), 1007x601@1.33125 (landscape) and 1280x720, light and dark; screenshots reviewed by eye.
- Android 16 edge-to-edge: navy header runs under the status bar with light icons; bottom nav clears the gesture bar. Verified on an emulator, then installed on the tablet (install only).
- Hints: no conceptual EI question gets the Ohm's law hint; generic-fallback share for AR/MK below 10%; unit tests pin key mappings.
- Score shown with a likely range; scale graphic validated with the dataviz palette validator (done: light #86b6ef #5598e7 #2a78d6 #1c5cab #104281 on #fff; dark #1c5cab #2a78d6 #5598e7 #86b6ef #b7d3f6 on #162238).
- Unit tests for: score range, ID migration, store sanitize, question picking (passage grouping), hint mapping, recommendations.

## Findings

Bugs and integrity
- begin() overwrites an active test without asking; Back from the runner lands on the start screen, whose Start button then silently discards the test.
- Question IDs are positional (set-id + index). Inserting or reordering a question in a set reassigns IDs and corrupts stats and review history.
- Array.prototype.at() on the home screen crashes iOS < 15.4 / Chrome < 92. Build target es2020 does not polyfill it.
- No error state when bank.json fails to load (first visit offline): blank page.
- Native alert()/confirm() for time-up, discard, import, erase: jarring, unstyled, blocks the timer thread.
- File input not reset after import, so re-picking the same file does nothing.
- iPadOS reports a Mac user agent, so the iOS install hint never shows on iPad.
- Status bar: CSS uses env(safe-area-inset-*) only; Capacitor 8.4+ injects --safe-area-inset-* because WebView < 140 reports wrong env() values. No SystemBars style set, so status icons are dark on the navy header.
- PWA manifest and theme-color still use the old blue (#1f5fbf).

Hints
- EI: regex /ohm|volt|amper|current|resist/ sends diode, fuse, transformer, unit and colour-code questions to "Ohm's law" (51 of 85).
- AR: 41 of 125 fall back to the generic method (ages, coins, consecutive integers, probability, unit rates, elapsed military time, geometry word problems, LCM timing).
- MK: 14 fall back (distance/midpoint, mean/median, probability, combining like terms, literal equations, <= inequalities).
- GS, AI, SI have only one subject-level hint each.

Content
- Lessons say "Answers and explanations are at the end of the chapter" (12 places), cite "Chapter N", "this book".
- Scores lesson is framed around one person's "70-80 goal".

UX and visual
- Home: duplicate title (app bar + hero), long intro, a non-clickable card styled like an action, "Quick AFQT test" takes 2 hours, 4th tile changes meaning, no clear next step.
- No short diagnostic; first-time users face a 55-question test.
- Runner: header scrolls away (timer hidden on long passages); progress bar is per-part only; disabled Next is low-contrast and unexplained; choices are buttons with role=radio but no arrow-key behaviour; no keyboard shortcuts; no focus move for screen readers; nav bar visible on part intros.
- Results: one exact-looking number; job-score names only in tooltips (invisible on touch); standard scores in <abbr> tooltips; weak "what next".
- Practice and Learn: flat lists with no grouping (AFQT vs career subjects), no subject badges, no progress.
- Lessons: long pages with no table of contents or practice call to action.
- Progress: no summary numbers, chart has no dates, empty state has no action.
- Desktop and tablet landscape: bottom nav stretched across the full width.
- No first-run goal setting; goal hidden in Settings.

Engineering
- main.ts is 916 lines holding every screen; split into view modules while redesigning.

## Decisions

- Score scale: five ordinal bands (below 31, IIIB, IIIA, II, I) because eight bands fail the lightness-step check; categories still named in text.
- Likely range: AFQT recomputed with each subject's correct count moved one binomial SD down and up. Sampling noise only; method error stays covered by the "estimate" wording.
- Stable IDs: set-id + 8 hex of SHA-256(question text + choices). Legacy positional IDs shipped today are mapped through an alias table in bank.json and migrated in place once.
- Tests: Quick check (4 AR, 6 WK, 4 PC, 4 MK, untimed by default, about 15 minutes) for a first score; "AFQT practice test" (55, CAT timing); full test unchanged.
- Dialogs: one accessible <dialog>-based ask()/notice(), with confirm() fallback where <dialog> is missing.
- Choices: native radio inputs inside labels (screen readers and arrow keys for free), keys 1-4/A-D and Enter.
- Wide screens (>= 900px): navigation moves into the header; phones keep the bottom bar.
- Government look stays USWDS-based; no seals, no official-site banner.

## Not doing now (recorded)

- Bookmarking questions, "report a problem" links, publishing the PDF guide as a release asset, more Assembling Objects figures (tools/ao.py).
- Generated-question template list must stay append-only (IDs store the template index).
